# Security boundaries

Lingora exposes public operational endpoints and authenticated self-account, learning-profile, and assessment endpoints. Auth0 Universal Login authenticates learners; the API verifies RS256 tokens, issuer, audience, required identity claims, expiry, optional `nbf`, verified email, and endpoint scopes. Missing Auth0 configuration leaves health checks public and private access closed. MCP and production hardening remain later milestones.

Secrets belong in environment-specific secret management. `.env` files are ignored; example local database credentials are intentionally disposable. Never use them in hosted environments or put client secrets in Vite configuration. Use environment-specific Auth0 tenants/applications, exact origins, and HTTPS outside local development.

Private endpoints resolve the student from the verified `(provider, issuer, subject)` mapping and accept no client-supplied identity selector. A route guard or Auth0 permission claim never replaces resource ownership checks. Profile and assessment operations verify ownership; foreign assessment identifiers return 404. Version checks reject stale writes, and per-student idempotency receipts prevent duplicate creation. Accounts are never merged by email; the shared tenant legacy linker excludes Lingora identities.

The SPA keeps tokens in memory, purges all private queries, cancels pending private requests, and unmounts previous-account forms on logout or identity change. Onboarding drafts are saved only to the authenticated backend, not persistent browser storage. Logout does not revoke an already issued JWT; its expiry remains the API validity bound. Do not store access tokens, recordings, or full conversations by default. The current logger and custom spans exclude arbitrary paths, query values, bodies, and headers. Run Uvicorn with `--no-access-log` as documented to avoid its separate full-URL access logs. Production reverse proxies and exporters require equivalent filtering. Production rate limits and trusted-proxy configuration are part of the later deployment/security milestone; no distributed limiter is claimed here.

Future AI output and ingested news are untrusted data. Schema validation, licensing checks, backend authorization, and database constraints remain authoritative. Student export/deletion, consent, retention, audit events, and pedagogical evidence controls must be implemented before a real learner pilot.

Run `make audit` for dependency advisories. The standard CI suite uses local fixtures and no live Auth0 or AI credentials. Real Auth0/ChatGPT connection testing is a separate nonproduction acceptance gate.
