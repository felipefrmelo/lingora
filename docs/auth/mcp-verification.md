# MCP development verification

Status: **in progress**. No real ChatGPT conversation or voice session has been verified. These notes do not claim Milestone 5 completion.

On 2026-11-05, the existing development tenant was inspected. A separate API named **Lingora MCP Development** was created with identifier `https://exhaustedly-overcultured-jeane.ngrok-free.dev/mcp`, RS256, per-application user-delegated authorization, and no machine-to-machine access. The API defines `profile:read`, `lessons:read`, `sessions:read`, and `sessions:write`. Its maximum and implicit/hybrid access-token lifetimes were set to 900 seconds and offline access enabled; the SPA policy was not changed.

Resource-parameter compatibility was already enabled on the shared tenant. CIMD discovery and issuer responses were enabled after approval. Dynamic CIMD registration remains disabled; the existing tenant-wide DCR setting was not changed. Public discovery advertises CIMD and issuer support. The public ChatGPT metadata document advertises `private_key_jwt`, authorization-code and refresh-token grants, and its stable callback. The registered ChatGPT third-party client has public Auth0 client ID `tpc_u4W4Bp3PuBdTUiRXZHNsPu`. Dashboard inspection also showed an existing Swim Coach MCP Production grant on this client; its refresh-token settings therefore affect that client across APIs. After approval, the client was granted the four defined Lingora MCP permissions for user-delegated access; the Swim Coach grant remained at six permissions, and client access to Lingora MCP remained denied.

The resource/client-scoped Lingora verification Action and matching legacy account-linker exclusion were deployed after approval. The dashboard reported both Actions up to date and the post-login flow live, with verification before account linking and the other Actions in their previous order. Local Action tests pass, but live authentication behavior still requires verification. The ChatGPT client has refresh-token rotation enabled, with a seven-day idle lifetime and a 30-day maximum lifetime; actual refresh and reconnect behavior still require live verification.

Auth0 marks the ChatGPT client as third-party and only allows it to use domain-level connections. The existing Google connection was already domain-level. After the user approved the shared-tenant impact, the dedicated Lingora database was promoted to domain level and Auth0 showed it available to the ChatGPT client. The promotion also makes this connection available to every third-party application in the shared tenant, not only ChatGPT.

An initial personal ChatGPT plugin connection for a signed-in Lingora database user reached consent and Auth0 reported a successful authorization-code exchange for the exact MCP audience. Auth0 also recorded a successful refresh-token exchange for the ChatGPT client and Lingora database connection. ChatGPT then reported **“Authentication succeeded, action discovery failed”**; this does not demonstrate successful MCP authorization or usable tools. Token rotation, expiry recovery, other login methods, and reconnect remain unverified. A subsequent reconnect opened a blank Safari window before reaching the diagnostic listener.

On 2026-11-06, a Google-account reconnect showed that signature, audience, and verified-email validation passed but the configured internal Auth0 `tpc_` client ID did not match the token's `azp`. Setting the listener's approved client to the exact ChatGPT CIMD metadata URL `https://chatgpt.com/oauth/client.json` allowed the verified token; ChatGPT reported the account connected and listed all seven expected tools. Temporary diagnostics logged status and validation categories without recording credentials or learner content.

After the learner enabled MCP access, a real text integration test recovered that Google account's prepared B1 lesson, started its session, changed its correction mode from free to balanced, and saved explicitly labelled simulated feedback with a short example. ChatGPT reported a successful completion receipt; the website showed the session as completed and displayed the saved feedback. Before enablement, the same tool call was denied. A separate voice journey, summary-only privacy acceptance, another-account isolation, and the remaining refresh/reconnect cases are still outstanding.

Never include that token in repository files or logs.
